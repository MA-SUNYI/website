How the Conversion Works

Models do not read letters or words. A tokenizer splits text into fragments drawn from a fixed vocabulary, and you are billed per fragment. Common English words such as value or report are usually one token. Uncommon words split into stems and suffixes, and a string like 2026-11-12 can break into four or five pieces because digits and hyphens sit in separate vocabulary entries.

Because the exact fragment list differs by model family, this tool works from measured ratios rather than from a vocabulary file:

  • English prose: about 4 characters per token, or 0.75 tokens per word
  • Code, JSON and markup: about 2.8 characters per token
  • Chinese, Japanese, Korean: about 1.5 characters per token

The auto mode samples the pasted text: it counts non-ASCII characters, braces and punctuation density, and picks the ratio that matches the dominant material. A prompt that is half spreadsheet dump and half instructions is averaged between the code and prose ratios, which is the right call in practice because the dump is almost always the expensive half.

Worked example. A support prompt reads 600 words of product policy plus a 40 line JSON customer record. Prose: 600 words is about 800 tokens. The record is roughly 1,400 characters, which at 2.8 characters per token is 500 tokens. Total 1,300 tokens. At $2.00 per million input tokens, one send costs $0.0026, and ten thousand sends a day is $26 a month. That is cheap until the same system prompt is resent with every follow-up message, at which point the policy half becomes the single largest line on the invoice.

Why the Estimate Is Often Low in Real Billing

The most common mistake is treating the user message as the whole prompt. It is not. A typical chat request carries the system instruction, tool or function schemas, the retrieved context, and every previous turn. In a six-turn conversation where each user message is 200 tokens and each reply 300 tokens, the fifth call alone resends about 2,200 tokens of history before the new question is even added. Multiply that across a support inbox and input tokens grow with the square of conversation length, not linearly with message count.

Two smaller traps are worth naming. First, formatting: markdown tables, indentation and JSON keys are punctuation-heavy and tokenize badly, so the same content sent as plain sentences can be 20 to 30 percent smaller. Second, retries: a failed JSON parse means paying for the input a second time, and pipelines that retry once on bad output quietly carry a 20 percent surcharge on every task.

The character rule of thumb is fine for prose and misleading for anything else. A URL of 90 characters can be 40 tokens. A 300 digit numeric field is closer to 150 tokens. If your prompt is mostly structured data, trust the code ratio and add margin.

Limits of This Tool

This is an estimate, not a tokenizer. It does not download vocabulary files, so it cannot reproduce provider counts to the token. Errors are smallest on plain English paragraphs, typically within 10 percent, and largest on mixed-format text such as logs or encoded payloads, where the estimate can be 20 to 30 percent off. Image and audio inputs are billed by dimensions or seconds and are not covered. Prices in the cost table are list rates and change frequently; verify against the provider's own pricing page before you commit a budget.

Frequently Asked Questions

Why does the same paragraph count as 240 tokens in one tool and 310 in another?

Each model family uses its own vocabulary. A word that is one token in one tokenizer can split into two or three pieces in another, and numbers and code split far more aggressively than prose. This converter applies one ratio to the whole text, so small differences between tools are expected.

How many tokens does a one-page PDF prompt use?

A dense single-spaced page of English is about 500 to 600 words, or roughly 700 to 850 tokens. Headers, tables and footnotes add structure tokens, so budget 900 to 1,100. Twenty pages of that will not fit in a small context window at all.

Can I just count characters and divide by four?

For ordinary prose that shortcut is within about 5 to 10 percent. It breaks on code, JSON, long numbers, URLs and non-Latin scripts, where the real count can be 50 to 100 percent higher than the shortcut predicts.

Does the number include the system prompt and chat history?

No. Only the pasted text is measured. In a real call the system instructions, tool definitions and earlier turns are appended and billed again, so the input actually sent is often two to six times the message a user typed.

Is the cost column accurate enough to bill clients from?

Treat it as planning. Prices are list rates captured for reference and providers change them without notice, and the token estimate carries a 10 to 20 percent error. Reconcile invoices against provider usage dashboards.

What happens when a prompt is longer than the context window?

Most APIs return an error rather than trimming silently, and a retry fails the same way. Long documents need chunking or retrieval so each call carries only the few thousand tokens that matter for the question.
