Binary is base two, so each position counts a power of two rather than a power of ten. Reading the digits right to left, the columns are worth 1, 2, 4, 8, 16, 32 and so on. To convert, add up the column values wherever a 1 appears and ignore the zeros.

The worked example is 1011: rightmost 1 is worth 1, the next 1 is worth 2, the 0 is worth nothing, and the leftmost 1 is worth 8. Total 1 + 2 + 8 = 11. That is the entire method — no tables to memorise, just doubling from the right and summing. An eight-digit byte covers 0 to 255, which is why so many technical limits sit at 255.

Binary shows up far more often than people expect: subnet masks, file permission codes, colour channels, bitmask flags in APIs and the output of any hex editor. Being able to read a byte by hand makes those numbers stop looking like noise.

Frequently Asked Questions

How do I convert binary to decimal by hand?

Write the place values 1, 2, 4, 8, 16, 32... under each bit starting from the right, then add only the values sitting under a 1. The sum is the decimal value.

What is the largest number in 8 bits?

255, which is 11111111 — all eight place values added together. Going one bit further to 9 bits reaches 511, which is why unsigned byte ranges always stop at 255.

How are negative numbers stored in binary?

Most systems use two's complement: flip every bit and add one. So -1 in 8 bits is 11111111. This lets the same addition circuitry handle signed and unsigned values.

What is the fastest way to convert a long binary string?

Group the bits into nibbles of four from the right, convert each nibble to a hex digit using 8-4-2-1, then convert the hex to decimal. It is much faster than summing dozens of powers by hand.
