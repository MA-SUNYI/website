Vercel's free plan enables Deployment Protection by default, which makes preview deployments — and sometimes the production domain — return 403 to any client that cannot complete an authentication challenge. Googlebot cannot, so it is refused, and Search Console reports the sitemap as unreachable while the same URL opens without issue in your browser.

The fix is in the project settings rather than in the code. Under Vercel, open Project Settings, then Deployment Protection, and disable Vercel Authentication for the production environment. Confirm with a request that identifies itself as Googlebot: if the response is 200 rather than 403, the block is gone. After that, resubmit the sitemap in Search Console so the URLs are recrawled.

Two related problems produce the same symptom. A robots.txt that disallows the sitemap path will stop the crawl even when the file is reachable, and a sitemap served from a different hostname than the canonical domain splits signals between two origins. Check both before assuming the platform is at fault — the 403 is the most common cause, but it is not the only one.

Frequently Asked Questions

Why can Googlebot not access my Vercel site?

Deployment Protection on the free plan returns 403 to unauthenticated clients, including Googlebot. Disabling Vercel Authentication for production resolves it.

How do I confirm Googlebot is really blocked?

Request the URL with a Googlebot user agent and inspect the status code. A 403 confirms the block; a 200 means the problem lies elsewhere.

Does the block affect users?

No. Browsers can complete the authentication challenge, so the site looks fine when visited normally while crawlers are refused.

What should I do after fixing it?

Resubmit the sitemap in Search Console and request indexing for the affected URLs. Recrawling usually begins within a few days.
