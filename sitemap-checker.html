A sitemap is only useful if it is valid, current and discoverable. Common failures are XML syntax errors, URLs that return 404, and pages that exist but were never added — the last being the most damaging, since those pages have no other route into the index.

Validation requires three checks. First, the XML must parse, with no unescaped ampersands and correct namespace. Second, every listed URL should return a 200; a sitemap full of redirects and errors signals neglect and delays crawl scheduling. Third, compare the URL count against the actual page inventory — the numerical difference is usually where the missing pages hide.

Size limits also apply. A single sitemap supports up to 50,000 URLs and 50 MB uncompressed, and larger sites need a sitemap index pointing at several files. Google accepts up to 500 sitemaps in an index, which is ample for almost any content site.

Frequently Asked Questions

Why is my sitemap not being picked up?

Check that it is declared in robots.txt or submitted in Search Console, that the XML parses without errors, and that Response headers return 200 rather than a redirect.

Does a sitemap guarantee indexing?

No. It signals that URLs exist and encourages crawling. Indexing still depends on content quality and crawl budget.

How many URLs can a sitemap hold?

Up to 50,000 URLs and 50 MB uncompressed. Beyond that, split into multiple files under a sitemap index.

Should every page be in the sitemap?

Only canonical, indexable pages. Including redirects, 404s or noindexed pages wastes crawl budget and dilutes the signal.
